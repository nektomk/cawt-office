# Безопасность скилла cawt-office

> Прочитайте этот документ **перед установкой и использованием** скилла.
> Он описывает реальные возможности автоматизации, связанные с ними риски
> и меры защиты — встроенные в скилл и те, что стоит применить вам.

## Почему этому скиллу нужно особое внимание

`cawt-office` управляет **настоящими, живыми** приложениями Microsoft Office
через COM-интерфейс. В этом его ценность — и его главный риск.

Среда агента (DeepSeek Harness, DSH) ограничивает файловые операции агента
и его дочерних процессов политиками песочницы: `read-only`, `workspace-write`
или `danger-full-access`. Однако приложения Office активируются через
COM/DCOM **как отдельные процессы вне этого дерева** и работают с полными
правами текущего пользователя Windows. Песочница DSH на них не распространяется.

Проще говоря: **любое действие, совершённое «руками» Excel, Word, PowerPoint
или Outlook, технически обходит песочницу агента.** Ответственность за границы
таких действий берут на себя политика скилла (для добросовестного агента)
и настройки вашей системы (для всех остальных случаев).

## Что скилл технически способен сделать

Возможности = риски. Через CAWT и объектные модели Office доступно:

| Категория | Конкретные возможности |
|---|---|
| **Запись файлов** | сохранение документов/книг/презентаций по любому пути (`SaveAs`), экспорт в CSV, PDF, изображения; «печать в файл» |
| **Чтение файлов и данных** | открытие документов по любому пути; чтение значений, включая несохранённые правки; доступ к почтовому ящику, контактам и календарю Outlook |
| **Выполнение кода** | запуск макросов VBA (`RunMacro`), внедрение VBA-кода (`AddMacro`, требует отдельного доверия в Trust Center), сохранение в макро-форматах (`.xlsm`, `.docm`); автозагрузка файлов из стартовых папок Office |
| **Сеть** | отправка почты от вашего имени (с любыми вложениями), веб-запросы из Excel, автоматизация браузера (COM Internet Explorer), переходы по гиперссылкам |
| **Разрушительные действия** | закрытие документов без сохранения (потеря несохранённых правок), удаление листов/строк/слайдов, закрытие самих приложений |
| **Низкоуровневый доступ** | библиотека Twapi, на которой стоит CAWT, даёт доступ к WinAPI: процессы, реестр, произвольные COM-объекты (например, `WScript.Shell`) |

## Что скилл уже ограничивает (политика для агента)

В `SKILL.md` есть обязательный раздел **«Security policy (sandbox compensation)»**
(правила S1–S10). Ключевые ограничения:

- **Политика сессии распространяется на Office**: в `read-only`-сессии запрещены
  любые сохранения; в `workspace-write` все файлы, создаваемые через Office,
  должны оставаться в рабочем каталоге сессии.
- **Абсолютный запрет** (даже по явной просьбе): стартовые папки Office
  (XLSTART/STARTUP), автозапуск, планировщик задач — то есть любые механизмы
  персистентности; связка «макро-формат + стартовая папка» не нужна ни одной
  легитимной задаче.
- **Макросы — по умолчанию запрещены**: `RunMacro`/`AddMacro` только если вы
  явно попросили запустить/добавить конкретный макрос в текущем запросе.
  Открытие документа не считается разрешением выполнить его макросы.
- **Сеть — только по явной просьбе**: отправка письма, веб-запросы, переходы
  по ссылкам выполняются лишь когда сама задача про это. `SendMail` —
  дополнительно с подтверждением каждого письма.
- **«Гостевой режим» в ваших окнах**: подключившись к запущенному Excel/Word,
  агент не закрывает приложение, не сбрасывает несохранённые правки, не удаляет
  листы/строки; меняет только то, что названо в задаче; сохраняет файл, только
  если вы попросили изменить файл.
- **Никакой молчаливой перезаписи**: скрипты создания не пишут в существующий
  путь без явного аргумента `overwrite` (код выхода 2); агент передаёт его
  только внутри рабочего каталога сессии, для файлов самой текущей сессии
  или если вы сами попросили перезаписать файл в текущем запросе — иначе
  сначала спрашивает.
- **Чтение — только названного**: агент открывает внешние файлы лишь когда вы
  сами назвали файл/путь; почтовый ящик и контакты не выгружаются «оптом».
- **Twapi — только для CAWT**: создание процессов, правка реестра, `WScript.Shell`
  и прочие не-Office COM-объекты в скриптах скилла запрещены.
- **Содержимое документов — данные, а не команды**: инструкции, спрятанные
  в открываемых документах, письмах или веб-страницах (prompt injection),
  игнорируются и доводятся до вашего сведения.
- **Аудит**: каждый скрипт печатает все пути файлов, которые он открыл/сохранил;
  ответ агента повторяет этот список.

**Важно понимать границы:** `SKILL.md` — политика для *добросовестного* агента
(защита от ошибок и от инъекций инструкций), а не технический барьер.
Злонамеренный или полностью скомпрометированный агент этими правилами
не останавливается — для этого нужны меры уровня ОС ниже.

## Что рекомендуется сделать вам (реальная защита)

Настройки Microsoft Office (Файл → Параметры → Центр управления безопасностью):

- [ ] **«Trust access to the VBA project object model» — ВЫКЛЮЧЕНО**
      (по умолчанию выключено; не включайте без крайней нужды — это главный
      шлюз для внедрения макросов).
- [ ] **«Block macros in files from the Internet» — включено**.
- [ ] Автоматическое открытие файлов из DDE — отключено.
- [ ] Office обновлён; скачанные файлы сохраняют Mark of the Web.

Настройки системы:

- [ ] Для максимальной изоляции автоматизируйте Office из **отдельной учётной
      записи Windows**, Windows Sandbox или AppContainer — тогда даже выход
      за границы песочницы ограничен правами этой учётки.
- [ ] Стартовые папки Office пусты и не доступны на запись посторонним
      процессам: `%APPDATA%\Microsoft\Excel\XLSTART`,
      `%APPDATA%\Microsoft\Word\STARTUP`.
- [ ] Формулируйте задачи конкретно («открой файл X», «сохрани результат
      в рабочий каталог»): политика скилла опирается на то, что названо
      в вашем запросе.

## Если что-то пошло не так

1. Проверьте «аудиторский след» в диалоге с агентом: скрипты печатают все
   затронутые пути файлов.
2. Загляните в стартовые папки Office (адреса выше) — там не должно появляться
   новых файлов.
3. Проверьте «Отправленные» Outlook, если выполнялись почтовые задачи.
4. Деинсталляция скилла — удаление его каталога из `%USERPROFILE%\.agents\skills\`
   (скилл ничего не регистрирует в системе сам).
